# AdPilot AI

**The AI Operating System for B2B Marketing — built for [SketchDeck.ai](https://www.sketchdeck.ai).**

> Stop optimizing for clicks. Start optimizing for pipeline.

AdPilot AI connects B2B advertising platforms (Google Ads, Meta, LinkedIn), the CRM (HubSpot) and analytics (GA4) into one AI-powered operating system. It monitors campaigns hourly, explains why performance changed, detects creative fatigue and anomalies, finds the audiences and creatives that actually produce qualified pipeline, recommends budget moves, and — only after human approval — executes them and measures whether they worked.

The core funnel: **Ad Spend → Lead → MQL → SQL → Opportunity → Pipeline → Revenue**.

It is not another dashboard and it does not replace Google Ads, Meta, LinkedIn or HubSpot. It is the intelligence and optimization layer on top of them.

---

## Product

| Area | What it answers |
| --- | --- |
| **Command Center** | How much are we spending? How much pipeline are we generating? What changed and why? What should we do next? |
| **Campaigns** | Sortable/filterable table with pipeline ROAS, cost/SQL, health (0–100) and fatigue (0–100) per campaign. |
| **Pipeline** | The B2B revenue funnel with volume, conversion, cost and value per stage; lead-quality comparison by channel. |
| **Creatives** | Creative → pipeline ranking (never CTR alone), fatigue, A/B tests, real assets when the platform exposes them. |
| **Audiences** | ICP intelligence: who converts by industry, company size, title, seniority, geography; over/under-index vs. spend. |
| **AI Agent** | Next best actions (what happened / why / action / impact / confidence) with Approve · Modify · Reject; budget optimizer (Top 3 ← Bottom 30%); what-if simulator; optimization log; AI impact. |
| **Insights** | Secondary intelligence — measured where a source is connected, labeled illustrative otherwise. Stack-consolidation business case. |
| **Integrations / Automation / Settings** | Independent integration health, hourly scanner, daily brief, fatigue thresholds and action-safety policy. |

Safety model: **OBSERVE → RECOMMEND → APPROVE → EXECUTE → MEASURE**. Real advertising changes require approval by default (max budget change 10%, max daily exposure $2,000, approval above $5,000/month — configurable).

## Architecture

See [docs/architecture.md](docs/architecture.md). In short: independent connectors normalize platform data → PostgreSQL (Supabase, RLS) → one analysis snapshot per window (`lib/analytics/snapshot.ts`) feeds every page, the hourly scan and the daily brief. All analysis is deterministic and unit-tested; no numbers are generated by an LLM.

```
app/            Next.js 16 App Router (server components, server actions, cron/API routes)
components/     UI (Tailwind v4 + Radix primitives + Recharts)
lib/            calculations · analytics · data repositories · auth · email · utils
agent/          detectors · analyzers · recommendations · optimizers · actions · prompts
integrations/   notfair (verified) · google-ads · meta · linkedin · hubspot · ga4 · search-console
jobs/           hourly-scan · daily-brief
data/demo/      SketchDeck demo data engine
database/       migrations (schema + RLS) · migrate runner · seed
tests/          unit + integration (vitest)
docs/           architecture · deployment · integrations/notfair audit
```

## Local setup

```bash
nvm use            # Node 22
npm install        # also installs the pre-commit secret guard (.githooks)
cp .env.example .env.local   # DATA_MODE=demo works with no credentials
npm run dev        # http://localhost:3000
```

**Local secrets live only in `.env.local`.** It is git-ignored, the pre-commit hook refuses to commit any `.env*` file except `.env.example` or any credential-looking string, and CI runs the same check (`npm run check:secrets`). Next.js and all npm scripts read `.env.local` automatically; production values go in Vercel environment variables.

Quality gates (also run in CI):

```bash
npm run typecheck
npm run lint
npm test
npm run build
```

## Database

```bash
npm run db:migrate   # applies database/migrations/*.sql (schema, indexes, RLS) using DATABASE_URL
npm run db:seed      # loads the SketchDeck demo dataset into Postgres (rows tagged source='demo')
```

Tables: organizations, users, org_settings, integrations, campaigns, ad_groups, ads, creatives, performance_metrics, contacts, companies, funnel_events, opportunities, pipeline_events, audience_segment_metrics, ai_recommendations, optimization_actions, scan_runs, daily_briefs, audit_logs. Row-level security scopes everything to the user's organization.

## Demo mode

`DATA_MODE=demo` (default) generates a deterministic, SketchDeck-specific dataset: 25 campaigns across Google, Meta and LinkedIn (Core Phrases search, competitor conquest vs. Tekla/SDS/2/Bluebeam/STACK, LinkedIn Chief Estimators / VP Estimating / AISC member firms, Meta lead forms and retargeting, …), 120 days of daily metrics, 68 creatives using SketchDeck's real RSA messaging, ICP segments, prior AI actions and scan runs. Seven performance profiles (high-performing, average, underperforming, fatiguing, high CTR/poor quality, low CTR/excellent pipeline, high CPL/excellent SQL) demonstrate that the system does not optimize on CTR.

The banner always shows 🟡 **DEMO DATA**. Demo creatives intentionally carry no media asset — AdPilot never fabricates creative images. Approving a recommendation in demo mode records the action without touching any live account.

## Live mode

`DATA_MODE=live` requires Supabase (auth + Postgres) and at least one integration. The proxy (`proxy.ts`) requires a signed-in user on every app route and fails closed if Supabase is missing. The hourly scan pulls each configured connector independently, normalizes rows, stores them, runs the analysis and stores recommendations. The banner shows 🟢 **LIVE DATA**; demo and live are never mixed.

### NotFair MCP (already connected — primary source)

The NotFair MCP connection in this workspace was inspected and verified on 2026-09-14. It exposes `search` / `executeRead` / `execute` over 125 capabilities; in the SketchDeck workspace **Google Ads (account 2175229247)** and **GA4 (properties/454640302)** are connected. Verified data: campaigns, budgets, bidding, daily metrics, Responsive Search Ad headlines/descriptions with performance labels, image assets with real URLs, conversion actions, GA4 key events (`hubspot_form_submit`, `hubspot_meeting_success`). Write capabilities (budget updates, pause/enable) exist and are gated behind AdPilot's approval workflow. Full audit: [docs/integrations/notfair.md](docs/integrations/notfair.md).

Runtime connection: NotFair uses OAuth 2.1 + PKCE (no API keys). In production, set `NOTFAIR_MCP_URL` and `ADPILOT_ORGANIZATION_ID` in Vercel, then click **Connect NotFair** on the deployed app's Integrations page — a browser-only OAuth flow (`/api/integrations/notfair/authorize` → `/callback`) that stores tokens server-side; no terminal required. For local development, `npm run notfair:auth` is a CLI alternative. Until authorized, the integration reports *not configured* — it never claims to be live.

### Google Ads

Flows through NotFair. A direct Google Ads API connector is scaffolded (`integrations/google-ads`) for organizations without NotFair and is intentionally not implemented beyond configuration checks.

### Meta Ads

`integrations/meta` implements the Marketing API (campaigns, daily insights incl. frequency, ads with creative `image_url`/`thumbnail_url`). Setup: create a Meta app, generate a system-user token with `ads_read`, set `META_ACCESS_TOKEN` and `META_AD_ACCOUNT_ID`. Not yet verified against a live SketchDeck account.

### LinkedIn Ads

`integrations/linkedin` implements the Marketing API endpoints for ad accounts, campaigns and daily analytics; creatives require Marketing Developer Platform approval and are not implemented until authorized. LinkedIn campaign names are already visible through GA4 (`linkedin / paid-social`) for attribution.

### HubSpot

Supply the HubSpot Service Key as `HUBSPOT_ACCESS_TOKEN` — in production via Vercel environment variables (see [docs/deployment.md](docs/deployment.md)), locally via `.env.local`. Verify without exposing the key: after deployment open `/api/integrations/hubspot/verify?key=<CRON_SECRET>`, or locally `npm run hubspot:verify`.

`integrations/hubspot` reads contacts by lifecycle-stage entry dates (`hs_v2_date_entered_*`), paid click ids and traffic-source drill-downs, plus deals (`amount_in_home_currency`, closed won/lost) through the v3 API, authenticated with the HubSpot Service Key. Property names were verified through the HubSpot MCP connection ([docs/integrations/hubspot.md](docs/integrations/hubspot.md)). **The portal connected in this workspace is the BOM Growth agency CRM, not SketchDeck's** — `HUBSPOT_ACCESS_TOKEN` must come from SketchDeck's own portal.

### GA4 and Search Console

Both read through NotFair. GA4 is connected and verified. Search Console is supported by NotFair but **not connected in the SketchDeck workspace** — connect it there to enable search-opportunity insights.

## Scheduled jobs

- `GET /api/cron/hourly-scan` — fetch → normalize → store → KPIs → anomalies → fatigue → campaigns → audiences → creatives → recommendations → record `scan_runs`. Scheduled once daily at 12:00 UTC in `vercel.json` by default, because Vercel's free Hobby plan caps cron jobs at once/day; see [docs/deployment.md](docs/deployment.md) for restoring true hourly cadence (Pro plan, or a free GitHub Actions schedule).
- `GET /api/cron/daily-brief` — daily 13:00 UTC: pipeline, revenue, ROAS, MQLs, SQLs, wins, problems, recommendations, actions; markdown + email HTML.
- Both require `Authorization: Bearer $CRON_SECRET`. CLI equivalents: `npm run scan`, `npm run brief`.

## Deployment

Vercel (web + API + cron) and Supabase (Postgres + auth). Step-by-step in [docs/deployment.md](docs/deployment.md). Use separate Production (live) and Preview/public-demo (demo) environments; live customer data is never served through an unauthenticated route.

## Security

Server-side secrets only; Supabase session required in live mode; RLS organization isolation; approvals restricted to non-viewer roles; cron endpoints secret-protected; every decision, execution and settings change is audit-logged. Integration failures degrade independently (e.g. "Google Ads 🟡 Connection issue" while Meta/LinkedIn/HubSpot keep rendering).
